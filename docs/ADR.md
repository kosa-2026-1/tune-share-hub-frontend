# Architecture Decision Records

## 철학

MVP 단계에서는 단순한 React/Vite SPA 구조를 유지한다. 새 의존성은 실제 중복이나 복잡도를 줄일 때만 추가한다.

---

### ADR-001: Vite + React 유지

**결정**: 프론트엔드는 Vite 6과 React 18 기반 SPA로 유지한다.

**이유**: 현재 코드와 빌드 설정이 이미 Vite에 맞춰져 있고, 초기 제품 검증에는 서버 렌더링보다 빠른 개발 속도가 중요하다.

**트레이드오프**: SEO나 서버 렌더링이 중요한 페이지가 생기면 별도 전략이 필요하다.

### ADR-002: JavaScript JSX 사용

**결정**: 현재는 TypeScript 전환 없이 JavaScript JSX를 유지한다.

**이유**: 기존 코드베이스가 JavaScript이며, 하네스 도입 범위에서 타입 시스템 전환은 별도 작업으로 분리하는 것이 안전하다.

**트레이드오프**: API 응답과 공유 모델에 대한 정적 타입 안전성은 낮다. 도메인 모델이 복잡해지면 TypeScript 전환을 재검토한다.

### ADR-003: API 모듈 분리

**결정**: 외부 HTTP 요청은 `src/api/` 하위 모듈에서 관리한다.

**이유**: 컴포넌트가 엔드포인트, 인증 헤더, 에러 매핑 같은 네트워크 세부사항을 직접 알지 않게 한다.

**트레이드오프**: 아주 작은 기능도 API 파일을 거치므로 초기 파일 수가 늘 수 있다.

### ADR-004: Bootstrap 기반 UI

**결정**: 기본 프론트엔드 UI는 Bootstrap 컴포넌트와 유틸리티를 우선 사용한다.

**이유**: 팀이 빠르게 일관된 화면을 만들 수 있고, 반응형 레이아웃과 기본 접근성 패턴을 직접 구현하는 비용을 줄인다.

**트레이드오프**: Bootstrap 기본 룩이 강하게 남을 수 있다. 필요한 경우 작은 커스텀 CSS로 브랜드 톤만 보정한다.
