# UI 디자인 가이드

## 디자인 원칙

1. 제품 화면을 먼저 만든다. 별도 요청이 없으면 마케팅 랜딩 페이지를 만들지 않는다.
2. 음악 콘텐츠를 빠르게 훑고 비교할 수 있는 정보 밀도와 명확한 계층을 우선한다.
3. 컴포넌트 상태(loading, empty, error, active)를 빠뜨리지 않는다.

## Bootstrap 사용 규칙

- 레이아웃은 Bootstrap grid, spacing utility, container를 우선 사용한다.
- 버튼, 폼, alert, modal, nav, card 등 표준 UI는 Bootstrap 컴포넌트를 먼저 검토한다.
- 커스텀 CSS는 Bootstrap으로 해결되지 않는 제품 고유 표현에만 제한한다.
- Bootstrap card를 모든 영역에 남발하지 않는다. 반복 아이템, 폼 그룹, 명확한 패널에만 사용한다.
- 접근성 속성과 반응형 동작은 Bootstrap 기본 패턴을 해치지 않는다.

## AI 슬롭 안티패턴

| 금지 사항 | 이유 |
|-----------|------|
| 의미 없는 gradient orb 배경 | 제품 정보보다 장식이 앞선다 |
| 보라/인디고 일변도 팔레트 | 흔한 AI 템플릿처럼 보인다 |
| 모든 섹션을 카드로 감싸기 | 앱 구조가 무거워지고 정보 스캔이 어려워진다 |
| "Powered by AI" 같은 장식 배지 | 기능 가치와 무관하다 |
| 과한 글로우/블러 효과 | 반복 사용 앱에 방해가 된다 |

## 색상

- 배경, 표면, 경계, 텍스트 색을 명확히 분리한다.
- 한 가지 색 계열만 반복하지 않는다.
- 성공/경고/오류 같은 시맨틱 색은 콘텐츠 색과 구분한다.

## 컴포넌트

- 버튼은 명확한 command에만 사용한다.
- 목록, 플레이리스트, 트랙 같은 반복 데이터는 일관된 행 높이와 간격을 유지한다.
- 아이콘이 필요한 버튼은 텍스트만 둔 버튼보다 익숙한 아이콘을 우선한다.

## 레이아웃

- 모바일과 데스크톱 모두에서 텍스트가 컨테이너 밖으로 넘치지 않게 한다.
- 고정 포맷 UI는 `grid`, `minmax`, `aspect-ratio` 같은 안정적인 치수 제약을 둔다.
- 카드 안에 다시 카드가 들어가는 구조는 피한다.

## 타이포그래피

- 큰 제목은 실제 페이지 또는 주요 화면 제목에만 사용한다.
- 카드, 사이드바, 툴바 내부 텍스트는 컴팩트한 크기를 사용한다.
- letter-spacing은 기본값을 유지한다.
